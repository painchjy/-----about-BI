# 智家商城售后中台系统现状与接口说明（节选）

> 文档编号：ZJ-TEC-2025-042　编写：架构组　版本：V1.8
> （本文件为 PoC 模拟语料，内容虚构）

## 1. 系统清单

| 系统 | 类型 | 说明 |
|---|---|---|
| ASS 售后系统 | 自研遗留（2015 年，Java 单体） | 售后单全生命周期管理，初审、审核、关单均在此系统 |
| OMS 订单系统 | 自研 | 订单与商品快照查询 |
| WMS 仓储系统 | 自研 | 验收、入库、换货出库 |
| 支付网关 | 外采 SaaS | 退款执行通道 |

ASS 系统归售后服务部与架构组共同维护，是公司售后业务的系统记录（SoR）。

## 2. 对外接口（节选）

| 接口 | 方法 | 说明 | 幂等 |
|---|---|---|---|
| createAfterSaleOrder | POST /as/orders | 创建售后单 | 否（重复提交会建多单） |
| queryAfterSaleStatus | GET /as/orders/{id} | 查询售后单状态与流转记录 | 是 |
| approveRefund | POST /as/refunds/{id}/approve | 退款审批（人工操作入口） | 是 |
| executeRefund | POST /pay/refunds | 执行退款（支付网关，需 idempotency_key） | 是 |
| arrangePickup | POST /wms/pickups | 安排上门取件 | 否 |

## 3. 核心数据表

- `as_order`（售后单主表）：单号、订单号、类型（退/换/修）、状态、金额、创建时间；
- `as_item`（售后商品明细）：售后单号、商品、数量、验收结论；
- `refund_record`（退款记录）：售后单号、退款金额、审批人、执行状态、幂等键。

## 4. 现状痛点

1. **初审全靠人工**：客服逐单阅读申请并比对受理规则，平均每单 4 小时，大促积压严重；
2. **无智能分流**：简单单（未拆封退货）与复杂单走同一队列；
3. **createAfterSaleOrder 不幂等**：客户重复点击会产生重复售后单，需人工合并；
4. **退款执行与审批脱节**：审批通过后需人工再到支付网关操作，平均延迟 6 小时。

## 5. 运行数据

日常售后单量约 1200 单/天；大促峰值 5000+ 单/天。
